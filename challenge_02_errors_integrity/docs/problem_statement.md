# 问题陈述与质量目标（Problem Statement）

## 业务背景

挑战 01（意大利面 → 架构）完成后，我们拥有了一套**有序**的杂货零售数据库：5 张表，维度（products / vendors / stores / categories）加一张交易事实表（sales）。

但「有序」不等于「可信」。本挑战（挑战 02 — 错误 → 诚信）提供的是同一业务的**结构化但充满噪音**版本——缺失值、重复交易、外键孤儿（`9999` 哨兵值）、数量/金额离群、类别命名漂移被有意注入。任何直接基于这份数据做的分析或预测都会被系统性误导。

## 质量目标

1. **错误审计** — 穷举缺失、重复、偏移类别、时区/格式不一致与异常峰值，形成可复核的完好清单。
2. **完整性修复** — 针对每类问题采用*原则性*修复：优先精确还原（从业务不变量反推），仅在确无信号时使用统计补值（均值/中位数/频率抽样等），并为每一步选择给出理由。
3. **验证结果** — 证明清洗没有引入偏置、没有扭曲关键分布（引用完整、金额自洽、前后统计对比）。
4. **透明文档** — 输出审计日志、变更摘要与可复现说明，供他人审核或扩展。

## 数据范围

| 表 | 维度 | 角色 | 已知问题 |
|---|---|---|---|
| products | 20 × 5 | 商品主数据（id/sku/name/category/vendor） | 干净（已核查） |
| vendors | 5 × 2 | 供应商参考 | 干净（已核查） |
| stores | 5 × 3 | 门店（id/name/city） | 干净（已核查） |
| categories | 5 × 2 | 品类层级 | 命名漂移 |
| sales | 2859 × 7 | 交易事实（txn_id/date/store/product/qty/price/amount） | 缺失、重复、孤儿、离群、金额不一致 |

## 成功标准（验收）

- 所有注入问题被发现并**修复或明确说明**。
- 每个补值步骤配有**理由与诊断**。
- 清洗后数据集重新训练基线，**无异常指标跳跃**。
- 全部笔记本与脚本**端到端运行、零人工干预**。

## 工作流

```
audit（审计）
   -> repair（修复：精确还原 > 统计补值）
        -> validate（验证：18 项引用完整性 + 前后分布对比）
             -> retest（基线重测：脏 vs 清洗）
```
